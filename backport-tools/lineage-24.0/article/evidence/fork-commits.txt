=== system/vold
fce7dadf6510b8ac728eca0f77672daa582e2bb8 2026-10-23
vold: Restore the legacy fscrypt session keyring

Kernels without FS_IOC_ADD_ENCRYPTION_KEY (4.9, as on sargo) can only take
fscrypt keys through the global session keyring. Android 17 removed that path,
so enablefilecrypto failed with "Inappropriate ioctl for device" and init
rebooted to recovery. Bring back isFsKeyringSupported(), installKeyLegacy(),
evictKeyLegacy() and the cache drop after eviction from LineageOS 23.2, with
inline keyctl wrappers since libkeyutils is gone.

=== system/core
5742820aad0e0c23dc295b22b655e986b87a7fc4 2026-10-23
init: Restore the fscrypt session keyring for old kernels

vold installs fscrypt keys into an "fscrypt" keyring in a session keyring
shared by every process when the kernel lacks FS_IOC_ADD_ENCRYPTION_KEY.
Android 17 dropped both setup steps; restore them as in LineageOS 23.2:
init joins a session keyring at second stage, and mount_all creates the
fscrypt keyring on encrypted devices.

=== system/zygote
d6dadb5e56c821e8dd44b13725d9de6e3085c733 2026-10-27
zygote: Skip capabilities the kernel does not know

Kernels older than 5.9 return EINVAL from PR_CAPBSET_READ for
CAP_PERFMON, CAP_BPF and CAP_CHECKPOINT_RESTORE (38-40). The child
process treated that as fatal and panicked while dropping the bounding
set ("Failed to check capability bound: GetCapBoundFailure(EINVAL)"),
so every native app zygote died at start on the 4.9 kernel. Chrome 156
runs its renderers in one, and system_server's process-start thread
then retried the dead socket for minutes, blocking all app starts.

A capability the kernel does not know cannot be in the bounding set,
so there is nothing to drop. The C++ zygote handles the same EINVAL
the same way.
