=== e7a12e10fc29c0f2d7954bd49cf3b268c81473a1 2026-10-26
cgroup: Take a cgroup_bpf reference for a cloned socket

cgroup_sk_clone() came from 4.9-stable ("cgroup: fix cgroup_sk_alloc()
for sk_clone_lock()") before this tree had a cgroup_bpf refcount, so it
takes only a cgroup reference. The BPF backport then added
cgroup_bpf_get() to cgroup_sk_alloc() and cgroup_bpf_put() to
cgroup_sk_free(), but not to the clone path. Each socket that
sk_clone_lock() makes, for example by accept(), drops a cgroup_bpf
reference it never took.

When the cgroup is removed, the count is at or below zero after the
switch to atomic:

  percpu ref (cgroup_bpf_release_fn) <= 0 (0) after switching to atomic
  WARNING: ... at lib/percpu-refcount.c:155 percpu_ref_switch_to_atomic_rcu

and cgroup_bpf_release() frees the cgroup's programs and effective
arrays and puts the cgroup while sockets in it can still run them.

Take the reference as upstream does since ad0f75e5f57c.

Fixes: cdb68a9f367a ("BACKPORT: bpf: decouple the lifetime of cgroup_bpf from cgroup itself")

=== f877f2a0e53c5fd017e5c8230b29eb47b0d78bed 2026-10-25
arm64: Do not pass an ld emulation to gold

With full LTO, modules are linked by gold through the LLVMgold plugin,
which rejects any -m emulation for bitcode input:

  aarch64-linux-android-ld.gold: error: unrecognized emulation aarch64elf

The ld-option probe passes because it runs gold without input files.
Only add the emulation when the linker is not gold; -EL/-EB still apply.
